# meta-autoware

OpenEmbedded/Yocto layer that builds the [Autoware](https://autoware.org) autonomous
driving stack on ROS 2 Jazzy as native packages. It is GPU-free and contains no machine
configuration, so it can be added to any BSP.

Unofficial community project, not affiliated with or endorsed by the Autoware Foundation.
Not safety-certified. Packages that need CUDA or TensorRT are not built.

## Dependencies

Use the branch of each layer that matches this layer's `LAYERSERIES_COMPAT`:

- [openembedded-core](https://git.openembedded.org/openembedded-core): `meta`
- [meta-openembedded](https://git.openembedded.org/meta-openembedded): `meta-oe`,
  `meta-python`, `meta-networking`
- [meta-ros](https://github.com/ros/meta-ros): `meta-ros-common`, `meta-ros2`,
  `meta-ros2-jazzy`

## Usage

Add the layer and its dependencies to `bblayers.conf`, then build an image:

```sh
bitbake core-image-autoware
```

No other configuration is needed: the layer enables its own `autoware-fixups` class.

| Image | Contents |
|---|---|
| `core-image-autoware-minimal` | system, vehicle, control |
| `core-image-autoware` | the above plus sensing, localization, planning, map |
| `core-image-autoware-dev` | the above plus simulation and devtools, not for production |
| `core-image-autoware-demo` | planning simulator demo, contains a non-commercial map |

Add your vehicle and sensor packages with `CORE_IMAGE_EXTRA_INSTALL`, or use the
`packagegroup-autoware-*` groups in your own image.

`AUTOWARE_SYSTEM_MONITOR_PLATFORM` selects the CPU monitor in `autoware-system-monitor`:
`raspi`, `tegra`, or empty for generic arm. It has no effect on x86-64.

Recipes under `generated-recipes/` are generated by
[ros-mash](https://github.com/robwoolley/ros-mash) and must not be edited by hand. Fixes go
in `classes/autoware-fixups.bbclass` or `recipes-thirdparty-bbappends/`.

This layer overlaps with `meta-ros2-jazzy`, which ships older `autoware_*_msgs` recipes
under the same names. The layer priority is set so that the recipes here take precedence.
